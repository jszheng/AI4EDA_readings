kicad-mcp-pro 是面向 KiCad EDA 工作流的 Model Context Protocol 服务器，让 Claude / Cursor / Copilot 等任意 MCP 智能体驱动原理图、PCB、ERC/DRC、DFM、BOM 与制造审查全流程。项目 8 月 10 日单日合入 5 个 PR（#652 抽取 PCB 矢量服务、#653 根原理图连线 sheet symbol、#654 抽取 PCB 文件格式服务、#655 移除废弃 PostScript 导出、#648 依赖批量升级）。工程化亮点：采用渐进披露（progressive disclosure）安全模型——默认 default profile 仅暴露 24 个只读评审工具而非完整 377 工具专家目录，写操作需 build、制造交付需 release（人工把关），expert/full 仅对可信客户端开放；遥测默认关闭。项目同时发布 PyPI 与 npm 包，持有 Zenodo DOI，通过 OpenSSF Best Practices Silver 认证，公开追踪 KiCad 编程接口覆盖率 76.3%。README 明确「诚实边界」：信号完整性 / 电源完整性 / EMC / 热工具为一阶闭式估算（约 5–10% 精度），是首轮快速评审而非场求解器或正式签核替代——这种「能力自陈 + 权限分级」的做法，对 AI Agent 接入 EDA 工具的可信治理很有参考价值。

🧩 Babel v1.3：开源 AI 原生 Chiplet 设计流程——5-Agent 流水线 + Issue Handoff 协议 + Spec-Code 三层双向追溯

Babel 是基于开源 EDA 工具链与 AI Coding Agent 的开源 AI 原生 Chiplet 设计流程，主张从自然语言需求到 GDSII signoff 全流程由 Agent 自动化完成。核心机制：①5-Agent 流水线 + Issue Handoff 协议——architect → guru-rtl → guru-verification → guru-synthesis → guru-pd → signoff，通过 labeled issue 触发交接，每个 Agent 有独立迭代收敛上限与 escalate-user 机制，超限自动暂停请求人类决策，下游发现问题可用 *-needs-fix 标签回流上游修正；②Spec-Code 双向追溯三层模型——RTL 文件头 @requirement / @spec_hash / @spec_ref、内嵌 SVA 断言 @verifies / @constraint、SDC 约束标签，REQ_ID 跨 PRD → ARCH → MAS → RTL → TB → SDC 全链路传播，由 babel_traceability.py 生成多阶段追溯矩阵；③变更传播 + Commit 质量门禁——Hook 检测上游 artifact 变更即标记下游 stale，git commit 前强制执行 RTL lint、REQ_ID 唯一性与 @spec_hash 一致性校验，防止上下文断裂。项目还附带面向电子工程毕业生的 16 章完整教程（AI 原生范式 / 规范驱动设计 PRD-ARCH-MAS / RTL 生成与验证闭环 / 逻辑综合 / 物理设计 / NPU 实战走读），并在 GitLink 同步镜像。这是当前少见的把「多智能体协作 + 需求可追溯 + 质量门禁」完整开源化的 Chiplet 全流程范式实现。

⚙️ HLSmith：专家知识引导的 C/C++→HLS 翻译智能体框架——PolyBench 上较 ChatHLS 几何平均加速 4.24×，100% 功能正确

专用 FPGA 加速器能带来显著性能与能效收益，但开发成本高昂，即便有高层次综合（HLS）仍需大量硬件专业知识。作者指出：前沿 LLM 虽有很强的软件生成能力，却缺少把基线 C/C++ 可靠翻译为高性能 HLS 设计所需的硬件直觉与流程性知识——难以选对架构、难以复现 HLS 专家的优化流程、难以在多样 kernel 上一致地施加硬件变换。HLSmith 由三部分组成：①HLS 优化专家库，把变换配方连同其适用性、前置条件与需规避的不安全场景一起「带守卫地」编码；②分阶段、反馈驱动的编排流程，仿照专家 HLS 开发实践引导智能体走完综合 → 瓶颈分析 → 优化循环；③工具接地的模型适配流水线，把商用前沿模型产生的优化轨迹转成训练数据，用于微调开源权重 LLM。在 PolyBench 上对比先前主流智能体编排框架 ChatHLS：HLSmith 几何平均加速 4.24×，且在软件与 RTL 仿真中每个 benchmark 都功能正确（ChatHLS 有效设计率仅 57%）；使用商用前沿模型与开源权重模型时，最高加速分别达 252× 与 138×。属于「智能体 + 高层次综合」方向近期最具工程说服力的结果之一。

⚡ G-Power：跨芯片知识聚合的架构级 GPU 功耗建模——MAPE 14% / R 0.88，较 AccelWattch MAPE 降 22 个百分点

GPU 功耗优化依赖快速功耗评估，因此需要架构级 GPU 功耗模型。但功耗标签采集极其耗时，既有工作只能用简单 microbenchmark 训练，导致 AccelWattch 等架构级模型精度偏低。港科大 Zhiyao Xie 团队提出 G-Power：不再局限于目标 GPU 自身的稀缺标签，而是借用其他已知 GPU 芯片提供额外知识基座，再在目标 GPU 上微调。方法为三阶段算法：①用额外已知芯片预训练构建知识基座；②注意力启发的聚合，刻画目标芯片与各已知芯片的相似度并据此加权融合多个基座；③在目标 GPU 上微调。在 4 款现代 NVIDIA GPU 上评估，G-Power 平均取得 MAPE 14%、相关系数 R 0.88，相对 AccelWattch MAPE 低 22 个百分点、R 高 0.36。这是「跨芯片迁移学习缓解 EDA 标签稀缺」这一范式在功耗建模上的又一有效验证，属 DAC 2026 正式发表成果。

🔋 PowerScope：首个 ML 驱动的「周期内（intra-cycle）」功耗估计框架——纯 RTL 仿真轨迹推理，中位误差 5.88%、提速约 80×

亚时钟周期分辨率的功耗估计对供电网络（PDN）设计、动态电压跌落分析、硅前功耗侧信道安全评估至关重要。工程上通常依赖商用布局后门级功耗分析，但这类流程计算极其昂贵，且随设计规模与工作负载长度增长而严重劣化。既有 ML 功耗估计框架虽能提速，却只处理平均功耗或逐周期功耗。PowerScope 是首个 ML 驱动的周期内功耗估计框架：推理阶段仅依赖 RTL 仿真轨迹，无需为每个工作负载跑布局后门级仿真与功耗分析。在多样化基准套件上，相对商用布局后门级功耗结果达到中位绝对百分比误差 5.88%、平均 9%，同时快约 80×。作者进一步证明，PowerScope 的预测可可靠用于下游的硅前功耗侧信道泄漏评估任务——把「ML 功耗代理模型」的用途从 PPA 估算延伸到安全签核前置分析。
