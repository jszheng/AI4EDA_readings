🤖 AgentDRC: Multi-Agent Algorithms for Spatially-Aware Automated DRC Correction——AgentDRC：面向空间感知自动 DRC 修复的多智能体算法

Design Rule Checking（DRC）违例修复仍是物理设计中耗时的瓶颈，即便有先进 EDA 优化也常需人工介入；既有 LLM 智能体方法受限于冗余上下文形状、对原始坐标空间推理不足与扁平化版图表示效率低下。AgentDRC 把迭代式 DRC 修正表述为多智能体算法，提出空间感知的验证与修正算法：重建关键形状间的结构化空间关系，并通过几何与语义约束检查验证修复；系统协调四个专用智能体感知多层级、多模态几何特征，过滤无关形状并迭代纠正违例。在困难违例上 pass@1 最高 30.4%、pass@5 达 55.7%，较最佳基线的 pass@5 提升 13.8 个百分点；作者承诺录用后开源全部代码与基准任务。属「后端物理设计 / 多智能体 DRC 自动修复（空间关系重建 + 几何/语义约束验证）」方向。

🔎 RTLDetective: Agentic RTL Debugging through Dataflow Analysis and Simulation-Guided Fault Localization——RTLDetective：以数据流分析与仿真引导故障定位实现智能体式 RTL 调试

LLM 智能体在 RTL 调试中展现潜力，但准确局部化功能错误并生成可靠修复仍具挑战。RTLDetective 提出多智能体框架，融合信号依赖分析、仿真引导故障定位与知识推理：从 RTL 代码构建信号依赖图，并从波形轨迹提取失败信息；轻量定位智能体预测期望的中间信号值，通过定向仿真干预加以评估，迭代探测信号依赖以隔离可疑逻辑并识别潜在故障位置；调试智能体结合上述证据、静态分析、硬件设计原则与 RTL Bug 模式知识库以及推理生成修正 RTL；框架跨调试迭代复用缓存上下文以降低推理开销。在 MEIC 基准上取得 86.1% 修复率，较最佳基线高 13.9 个百分点，且 LLM 调用次数更少。属「功能验证 / 智能体式 RTL 调试与修复（信号依赖图 + 仿真干预 + 知识库推理）」方向。

🧩 CPU-Eval: Evaluating Large Language Models for CPU Hardware Code Generation——CPU-Eval：面向 CPU 硬件代码生成的 LLM 评测基准

VerilogEval 等基准推动了 LLM 生成硬件描述语言（HDL）的快速发展，但近期 HDL 生成系统在该基准上通过率已超 90%，难以进一步区分能力差异。CPU-Eval 从 6 款 CPU 构建 339 道 HDL 生成题，取材于包含已流片家族在内的真实 CPU 设计，覆盖从小型嵌入式核到可运行 Linux 的乱序核，代码涵盖 SystemVerilog、Chisel 与 SpinalHDL；每道题要求 LLM 完成真实 CPU 开发任务——生成 HDL。在 7 个前沿 LLM 上，CPU-Eval 的平均 pass@1 比 VerilogEval v2 Spec-to-RTL 低 45.14 个百分点，暴露出高通过率掩盖的能力差异；源码行数更多的子模块 pass@1 更低，说明细粒度模块化设计有利于 LLM 辅助硬件生成；使用较少见 HDL 编写的 CPU 上 pass@1 也更低，提示部署前应验证模型对目标 HDL 的熟练度。属「前端 RTL / 真实 CPU 硬件代码生成基准」方向。

🧵 SlotFill: Repairing Lossy SoC Communication Traces for Post-Silicon Validation——SlotFill：修复硅后验证中丢失消息的 SoC 通信轨迹

硅后验证依赖 SoC 组件间通信的消息轨迹，但追踪缓冲与监视器会丢消息，且往往不留丢失痕迹。SlotFill 的目标是把每条被删除的消息放回正确的间隔、并恢复其类型与顺序：为剩余消息之间的每个空隙分配固定数量的槽位，由 Transformer 模型为每个槽位填入一条消息或判定为空，因此输入不会暴露究竟丢失了多少消息；模型还利用幸存消息的监视器字段（时间戳、事务 ID、地址）。在 4 核与 8 核系统的整程序 gem5 轨迹（20.7 亿条消息）上，15% 丢失率时最高精确恢复 97% 的被删消息，50% 丢失率时恢复 87%；时间戳较粗时，15% 丢失率下仍可恢复 76%–83%。属「功能验证 / 硅后验证（Transformer 轨迹修复 + 丢失消息重建）」方向。
