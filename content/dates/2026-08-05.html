ai2.work 发布深度行业分析，系统梳理 EDA 智能体从"人类在环的 Copilot"向"自主闭环的 Autonomy"演进的最新态势：

⚡ LACE：LLM 辅助的多智能体敏捷 RISC-V 指令扩展框架——pass@1 从近零跃升至 72.8%，面向自定义指令的 RTL 敏捷生成

为特定应用定制 RISC-V 自定义指令能显著提升能效，但其 RTL 实现高度依赖专家手写、既慢又易错，现有 LLM 方法在"指令语义→可综合 RTL"这一长链任务上几乎失效（pass@1 接近 0）。LACE 提出一个多智能体框架，把指令扩展拆成可协作的子任务：规格理解智能体、RTL 起草智能体、验证/仿真反馈智能体与迭代仲裁智能体协同，借助仿真与形式反馈闭环不断修正生成的 RTL，直到通过功能验证。在自定义指令基准上，pass@1 从近零提升至 72.8%，把"专家数周的手工 RTL"压缩到智能体可迭代生成的量级。已开源：github.com/UMN-ZhaoLab/LACE。
核心创新与价值：把"敏捷指令扩展"从专家手工 RTL 升级为多智能体驱动的 RTL 生成-验证闭环——延续本站 RTL 生成主线（VeriRefine 五层审计 / VClare 规格修复 / ARES 成本感知优化），且首次在"RISC-V 自定义指令"这一高价值子任务上给出可观的 pass@1。对想用 LLM 做领域专用指令集扩展的团队，LACE 的"子任务拆分 + 仿真反馈闭环"是可直接借鉴的方法论。

📐 Fovea：物理含义感知的晶圆级设计空间探索——决策域引导的跨保真度精炼，端到端加速 4.13×（最大 7.80×）

晶圆级（wafer-scale）加速器把海量计算单元集成到单一芯片，其设计空间探索（DSE）需在"架构决策"与"物理实现（布局、热、功耗、良率）"之间反复权衡；传统 DSE 要么用低保真模型导致物理含义失真，要么用高保真仿真导致搜索成本爆炸。Fovea 提出物理含义感知（physical-implication-aware）的晶圆级 DSE，核心是决策域引导的跨保真度精炼（decision-domain-guided cross-fidelity refinement）：先在决策域上定位对物理指标最敏感的参数，再针对性地提升局部保真度，避免对全空间无差别地做昂贵高保真评估。在 70/70 对晶圆级设计对上恢复出最优解，端到端加速 4.13×（最大 7.80×），在保真度-成本前沿上显著优于均匀保真度与朴素贝叶斯优化基线。
核心创新与价值：把"物理实现含义"显式注入 DSE 的决策空间，用"决策域引导而非参数域盲目采样"来分配保真度预算——延续本站物理设计（布局/热/功耗/良率协同）与"智慧体/搜索驱动的 DSE"（ReviewDSE 白盒 DSE）主线，且专门针对晶圆级这一超高复杂度场景，对Cerebras/Wafer-scale AI 类加速器的设计方法论有直接参考价值。

📐 DiffPower：GPU 加速的可微开关功耗分析与优化——1002× 加速、toggle-rate 相关性 r=0.96、梯度单元面积 2.98×、power virus 2.13×

开关功耗是先进节点下的主导功耗成分，但精确开关活动分析（toggle-rate 传播）传统上慢且不可微，难以嵌入梯度优化。DiffPower 提出GPU 加速的可微开关功耗分析：把 toggle-rate 传播与功耗估算写成可在 GPU 上并行、可反传的形式，使"功耗"成为可被梯度下降直接优化的目标。关键结果：相对主流工具 1002× 加速；与黄金参考的 toggle-rate 相关性 r=0.96；所得梯度使单元面积相对无梯度基线缩小 2.98×（更紧的面积-功耗权衡）；在 power virus（最坏功耗模式）搜索上找到高出 2.13× 的峰值功耗。这意味着布局后的局部重综合/缓冲插入可以在"功耗梯度"指导下进行，而不必反复调用昂贵的签核级功耗分析。
核心创新与价值：把"可微功耗"带入 GPU 并行优化回路——延续本站物理设计（布局功耗 / 梯度优化 / PPA）主线（LEAP 布局功耗、ARES RTL PPA 优化），补齐了"开关活动可微化"这一关键拼图，对 leakage/switching 混合目标下的梯度驱动 EDA 优化具有基础工具价值。

📐 LEAP：面向布局功耗的自监督逐周期 toggle 传播模型——7.6× 加速、PR-AUC 0.99、LEAP-Power MAPE 4.55%、比基线快 5.3×

布局阶段精确预估功耗（尤其开关活动）对 PPA 收敛至关重要，但现有方法要么慢（门级仿真）、要么不准（纯统计估算）。LEAP 提出自监督的逐周期 toggle 传播模型：从已有仿真数据中自监督学习"信号在每个周期如何翻转并沿网表传播"，无需昂贵的人工标注即可预测布局阶段的逐周期开关活动，进而估算布局功耗。关键结果：相对黄金参考 7.6× 加速；异常翻转检测 PR-AUC 达 0.99；其功耗模型 LEAP-Power 的 MAPE 仅 4.55%，且比基线方法快 5.3×。这把"布局功耗"变成布局引擎可实时调用的快速反馈信号，支撑功耗感知布局。
核心创新与价值：用自监督逐周期建模替代"标注昂贵 + 慢速仿真"的功耗估算范式——延续本站物理设计（布局功耗 / RTL-Sequencer 时序 / 梯度功耗）主线，且已 DAC 2026 录用，是 HKUST Zhiyao Xie 组在"物理设计快速可微/可学习的 PPA 代理模型"方向上的延续，对功耗感知 P&R 与早期 DSE 有直接工程价值。

✅ Forbench：符号仿真助你的 testbench 更「形式化」——字级符号仿真框架 + Python 接口，加速形式验证收敛

形式验证需要把意图写成严谨的属性/断言，但工程师通常以仿真 testbench 形式表达意图，二者之间存在鸿沟；纯仿真覆盖不全、纯形式门槛高。Forbench 提出一个字级（word-level）符号仿真框架，用符号值驱动仿真，把 testbench 中的隐式意图提取为可形式检查的内容，从而"让 testbench 更接近形式化"。框架提供友好的 Python 接口，便于集成进现有验证流程，并给出将符号仿真结果转化为形式化属性的路径，降低形式验证的接入成本。
核心创新与价值：把"符号仿真"作为"仿真 → 形式化"的桥梁——延续本站功能验证（CircuitProver / Rtl2lean / VeriRefine / OpenFV 开源流水线）主线，补上"从 testbench 自然语义抽取可形式化约束"这一常被忽略的入口环节，对希望逐步从仿真走向形式保证、又不想一次性重写属性的团队尤其实用。

⚡ FinHardBench：LLM 能为金融计算生成「时延感知」硬件吗？——33 金融任务 × 6 LLM × 1530+ 轮，功能正确率仅 19–61%

金融计算（风控、量化、加密）对硬件时延极度敏感，但现有 RTL 生成基准几乎不考察"时延感知"这一真实部署约束。FinHardBench 是首个面向时延感知金融硬件生成的基准：覆盖 33 个金融任务，在 6 个 LLM 上跑了 1530+ 轮生成实验，系统评估 LLM 能否产出既功能正确、又满足时延目标的硬件。结果发人深省——即便最强模型，功能正确率也仅落在 19–61%，且"时延感知"几乎普遍缺失：模型要么生成错误功能、要么忽略时延约束。
核心创新与价值：把"时延"作为 RTL 生成的一等约束引入评测——延续本站 RTL 生成（VerilogEval / RTLLM / FinHardBench 类任务基准）主线，且首次针对金融计算这一高价值、强时延约束的垂直场景给出量化缺口。对 LLM 硬件生成研究而言，它划出了"能写对"与"能写快"之间的真实差距，是 RTL 生成评测从"功能 pass"走向"约束感知 pass"的重要一步。
