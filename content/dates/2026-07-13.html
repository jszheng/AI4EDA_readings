🏭 Synopsys 计划停供部分晶圆厂制造控制软件，资源转向高毛利 AI 芯片设计

据路透社（7 月 7 日）报道，美国 EDA 巨头 Synopsys 计划停止提供一套被全球半导体制造商广泛使用的生产流程控制软件，将资源转向利润率更高的 AI 设计业务。Synopsys 已于 2026 年 4–5 月陆续通知 三星电子、SK 海力士、铠侠（Kioxia）、Qorvo 等十余家芯片制造商，告知相关产品进入"终止生命周期（EOL）"状态，不再提供未来新版本，仅履行现有维护义务。

  • 受影响产品主要为设备工程系统（EES）与故障检测与分类（FDC）软件——充当晶圆厂的"中枢神经"，实时监控生产流程、在缺陷演变为代价高昂的良率损失前预警
  • 公司同时裁撤数十个相关岗位，并计划于 2026 年 7 月内完成与各厂商维护义务的谈判
  • 官方声明确认"停用部分传统制造分析产品"，以聚焦最高价值产品；部分客户（如三星）已在自研替代工具
核心看点：这是头部 EDA 厂商战略重心从制造侧分析软件向AI 驱动芯片设计倾斜的明确信号——与本站长期跟踪的"Agentic EDA / AI 原生设计"主线直接呼应，也预示晶圆厂 IT/OT 软件正从"工具堆叠"走向"平台化 + AI 原生"重构。

GitHub · 开源 EDA Agent · 2026-07-13 · Naman Ranka

🔧 siliconcrew：开源自主 LLM Agent，自然语言 → GDSII 全流程（Verilog 生成 + OpenROAD 综合）

Naman Ranka 发布开源项目 siliconcrew（MIT 许可证），是一个面向硬件设计的自主 LLM Agent：从自然语言规范出发，经 Verilog 生成、Icarus Verilog 仿真/lint、OpenROAD 综合（Docker）、波形调试、PPA 指标提取，并集成 SymbiYosys 形式验证，目标直指 SkyWater 130nm 的端到端 RTL→GDSII。

  • 采用 ReAct Agent + 迭代调试，specification-first 工作流（YAML），支持多文件设计、约束驱动优化循环
  • 内置 MCP 服务器（SSE / HTTP 远程传输）、工具自动发现、CVDP 基准评测框架，可复现、可容器化打分
  • 路线图中包含 Google XLS / DSLX 高层次综合前端、设计空间探索（DSE）等
核心看点：siliconcrew 把"Agentic EDA"从单点 RTL 生成推进到含物理实现（综合/形式验证）的闭环，是开源社区少见的完整 NL→GDSII Agent，与工业界 Siemens Fuse、Cadence ChipStack 形成"开源 vs 商业"的能力对照。

GitHub · 开源 EDA MCP · 2026-07-13 · ariklapid

🔧 pyslang-mcp：只读 MCP 服务器，为 AI Agent 提供编译器背书的 Verilog/SystemVerilog 语义分析

ariklapid 发布 pyslang-mcp（已上架 PyPI 与 MCP Registry，本地 stdio 运行），是一个只读的 Model Context Protocol 服务器，封装 pyslang，让 AI Agent 针对已解析/精细化的 HDL 提出编译前端级别的问题——而非简单文本搜索：

  • 可查询 design unit / interface / package 清单、编译前端诊断（diagnostics）、实例层次（instance hierarchy）、符号声明与引用、.f filelist 展开结果
  • 刻意保持只读边界：模型负责起草 RTL，pyslang-mcp 充当"编译器背书"的读取 / 检查 / 解释器，降低 IP 保护工作区的暴露面，适合本地与 CI 环境
核心看点：pyslang-mcp 直击 LLM 生成 HDL 时"表面合理但语义错误"的痛点——把 Agent 的 RTL 草拟与编译前端验证解耦，与 siliconcrew（写 RTL）形成"起草 + 校验"的能力互补，是开源 EDA Agent Skills / MCP 生态从"能写"走向"写对"的关键一环。

✅ LLM Assisted Verification Assertion Generation: Challenges and Future Directions

面向断言驱动验证（ABV）的系统性综述与前瞻，聚焦 LLM 辅助生成 SystemVerilog 断言（SVA）。文章指出 ABV 长期依赖验证工程师从规格手工编写断言、耗时且易错，而 LLM 正被探索用于从设计规格生成 SVA。本文梳理了近期工作所采用的不同 SVA 生成方法，并提出核心问题：如何让 LLM 断言生成变得系统化、质量可感知（quality-aware）？针对每类挑战，文末给出关键要点（Key Takeaways）与方法论指引，帮助以更高质量、更低风险生成断言集。
核心创新：LLM 辅助 SVA 生成全景综述 + "系统化 / 质量可感知"框架问题 + 分挑战（方法、质量、可维护性）方法论指引
