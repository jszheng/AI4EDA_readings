🤖 FluxBench：端到端 EDA 工作流中 AI Agent 的真实能力评测

现有评测多孤立考察单模型在单任务上的表现，难以刻画 agent 系统在完整 EDA 流程中的差异。本文提出 FluxBench，在统一 prompt / 工具环境 / 工艺库下系统评测 AI agent 的端到端 EDA 工作流能力，覆盖开源工具链 RTL 生成与商用工具 RTL-to-GDS 两类场景，评估 RTL 代码生成、迭代修复、工具反馈利用、逻辑综合、P&R、ECO 自动化；并引入 Token ROI 成本效率指标。
核心结论：即便基于同一基座模型，不同 agent 系统架构性能差距达 86.27%；同性能 agent 的 Token ROI 差达 105.92×。PicoRV32 RTL-to-GDS 中 FluxEDA 端到端得分 97.94，超配 domain-specific EDA skills 的 Claude Code 8.39×。结论：domain skills 不足以提升大规模 EDA 场景表现，agent 系统设计与基座模型能力共同决定成败。
核心创新：统一环境下的工具交互式 EDA agent 基准 + Token ROI 成本效率指标；揭示"系统架构 > 单模型"与"skills 非银弹"——延续本站对 RTL-to-GDS 闭环（CLOSER-Bench）与 agentic EDA 评测（ArchEval / PDAgent-Bench）的跟踪。

🔧 MechMem-RTL：复用验证确认的机制记忆做 LLM 驱动的 RTL 修复

修复复杂时序逻辑错误需复用过往调试经验。现有 RAG 依赖任务文本相似度提供经验，但自然语言难以反映周期级硬件执行语义，常误导模型。本文提出 MechMem-RTL：不再依赖文本相似度，而是复用验证器确认的修复记录——每条记录严格关联触发证据、诊断出的失败机制、局部修复动作、保持约束与验证摘要；仅当确定性验证器证据与存储触发严格兼容时才注入历史记录，否则仅用当前验证器证据。
核心结论：在 48 个公开时序 RTL 任务、6 个修复模型上，最多 2 次尝试即解决 288 个 task-model 对中的 180 个，优于标准反馈修复（109）与任务相似度 RAG（107）。
核心创新：以"验证确认的机制记忆"替代文本相似度 RAG 做 RTL 修复——延续本站对 LLM RTL 修复/验证闭环（VeriPilot / ChipFuzzer / Evidence-Driven HLS）的跟踪，把"可信经验复用"落到实处。

📐 Rtl2lean：自动化 RTL-to-Lean 翻译 + 分层定理生成与引理复用

交互式定理证明器提供 RTL 的强正确性保证，但将其用于现有 SystemVerilog 需大量手动语义建模与证明构造。本文提出 Rtl2lean，自动将 RTL 翻译为可执行 Lean 4 模型并构建分层定理库：生成模型将硬件执行表示为纯状态转移函数；四层定理框架覆盖组合语义、时序更新、单周期行为与可达性/不变量。
核心结论：当高层属性无法由现有定理库 discharge 时，LLM 证明循环从证明上下文提议中间引理并经 Lean 反馈验证，仅被 Lean kernel 接受的引理进入可复用池。6 个设计生成 403 条定理全部经 Lean 校验，358 条基础引理中 287 条可自动复用（80.2%）。
核心创新：RTL→Lean 自动化翻译 + LLM 证明循环 + 可复用引理池——延续本站对形式验证（Lean/Coq/SVA 生成）方向的跟踪，把机器检查 RTL 证明库的构建成本大幅降低。

📐 Provably Good Prim-Dijkstra Revisited：经典 VLSI 布线问题的 LLM 新理论与实用算法

LLM 可能让"精确但沉睡"的算法问题重新变得可实践。本文以此重新审视长期开放、却又被实际工作绕过的经典 VLSI 布线问题 Prim-Dijkstra routing（其仅终端 Manhattan 复杂度数十年未决）。

📐 CoEvoP&R：用 LLM 协同演化布局目标 + 布线反馈

解析布局器依赖可微目标（HPWL + 密度惩罚等代理指标），但与下游布线/时序质量错位。本文提出 CoEvoP&R：LLM 框架自动演化解析布局目标——每代 prompt 融合受限目标接口、基线上下文与带布线相关反馈（布局、时序代理、布线工具）的归档候选；LLM 提出可读可微目标，嵌入 DREAMPlace 验证、经时序代理与真实布线器评估并存储反馈以引导后续代数。
核心结论：在 8 个 ChiP-Bench Nangate45 设计（3 seed）上，布线后线长 -16.9%、拥塞 -36.7%，WNS 改善 0.70ns、总负 slack 减 912ns；8 个 ICCAD 2015 Superblue 上线长 -5.4%、拥塞 -23.2%。代码已开源。
核心创新：LLM 演化可微布局目标 + 布线/时序反馈闭环（可读、可解释、可部署于解析布局 flow）——延续本站对布局优化（DREAMPlace / GNN Placement）与"LLM+物理设计"主线的跟踪。

📐 CLDRoute：面向物理设计可布线性图生成的条件隐扩散

准确的可布线性估计可减少昂贵的布线后迭代。已有学习方法将其视为确定性预测（映射布局特征到单一拥塞/DRC 结果）。本文将其重构为条件生成问题，把布线拥塞与 DRC 违例建模为空间结构化可布性场。CLDRoute 用物理感知条件化与任务特定潜建模分别处理拥塞与 DRC 图特性，支持基于样本的推断，对同设计产出均值预测 + 空间不确定性估计。
核心结论：在 CircuitNet 2.0 (N28) 上——DRC 生成 SSIM 0.9678 / MAE 0.0028 / TopK@1% 0.3494；拥塞生成 SSIM 0.9031 / MAE 0.0286 / NZ-Pearson 0.3692。为布局期可布线性提供更实用的"期望 + 不确定性"视图。
核心创新：扩散模型生成可布性场（拥塞 + DRC）并给出不确定性——延续本站对可布线性预测（Package Floorplanning / AttentionCap）与"生成式物理设计"主线的跟踪。

🤖 CLOSER-Bench：面向硬件 Agent 的预算化跨阶段设计收敛评测

硬件工程给 coding agent 带来 pass-at-k 难以刻画的长程工作：进度连续、工具反馈延迟且异构、后端失败可能需改 RTL 而非调参。现有基准各自测 RTL 生成/修复/验证/PPA/物理实现，难判断 agent 跨抽象边界的成败。本文提出 CLOSER-Bench，受控评测"预算化跨阶段设计收敛"——对同一设计与隐藏目标，配对 spec-to-RTL、RTL-to-GDS、spec-to-GDS 任务，记录每次仿真/综合/STA/P&R 调用，衡量最终质量、anytime 进度、工具成本与跨阶段恢复。
核心结论：基于开源 Verilator / Yosys / OpenROAD / KLayout / Sky130 + Harbor agent harness。10 任务 pilots 暴露"完成—收敛"鸿沟：3 个 agent 解局部 AXI 修复，而配对的验证-收敛任务区分出 frontier agent 与两个 otherwise 成功基线。验证完整 RTL-to-GDS flow 并构建 macro-based AXI/DMA 流式加速器。
核心创新：把硬件收敛建模为预算化序贯决策问题（而非孤立代码生成）——与 FluxBench 共筑"RTL-to-GDS agent 闭环评测"双支柱，延续本站 agentic EDA 评测主线。
