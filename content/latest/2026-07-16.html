📐 CLIP-3D: Closed-Loop Evaluation of Performance and Physical Constraints for 3D ICs

3D 集成在更小面积内塞入更强算力，但候选设计的实际吞吐取决于其物理布局：哪个宏单元落在哪一层、热点落在何处、cache 几何如何映射到访存周期。架构模拟器（如 gem5）只在理想时序下报告 IPC，并不产生决定真实 BIPS 的逐块功率图、cache 周期计数或 3D 布局。本文提出 CLIP-3D，一个左移（shift-left）flow，在调用任何签核工具前，就把 3D 布局驱动的热 / 互连 / cache 效应暴露给早期架构探索：

  • 阶段一：将架构配置提升为物理块表示——McPAT 算逐块功耗、CACTI 算 cache 几何/访存周期、HotSpot 兼容的 3D 堆叠离散化
  • 阶段二：跑解析的 3D 热感知布图规划器，目标函数内嵌由 HotSpot 稳态算子线性度与 CMOS 功率–频率分解导出的闭式可持续频率表达式
  • 联合优化：跨层宏分配与层内布局为真实 BIPS 而非"HPWL + 温度"代理目标共同优化
出自 Bei Yu / Tsung-Yi Ho 团队（与本站 7/3 收录的 Chiplet3D 同一作者群）。
核心创新：3D-IC 性能–物理约束闭环节估 + 闭式可持续频率 + 为真实 BIPS 联合优化跨层/层内布局

📐 ORRAM: An OpenROAD-Integrated RAM Generator Using Standard Cells

在 turnkey ASIC 设计流程中，存储推断仍是重大挑战：从 RTL 推断触发器会生成数千个密集互连实例，拖慢流程并损害性能；存储编译器多为第三方、PDK 专用。本文提出 ORRAM，一个内置于 OpenROAD 的标准单元存储生成器：

  • 给定标准单元库，产出已布局布线、无需定制 bitcell 或外部工具的 RAM 块，时序验证经 OpenSTA
  • 支持任意字长 / 字数、掩码粒度、多端口读、列复用、锁存存储，并自动做 PDK 无关单元选择，兼容 sky130hd 与 NanGate45
  • 在 SkyWater 130nm 上比特密度与历史 DFFRAM 持平，功能集大幅扩展；源码为 OpenROAD 项目一部分（发表于 2026 OSCAR Workshop）
核心创新：OpenROAD 原生标准单元 RAM 生成器 + OpenSTA 时序验证 + PDK 无关 + 已布局布线输出
标签：物理设计 · OpenROAD · 存储生成 · RAM · 标准单元 · 开源EDA
