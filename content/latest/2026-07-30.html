🤖 Synopsys × Microsoft × AMD：首个跑在 Microsoft Discovery 上的自主 EDA 工作流——debug closure 周期降 25–40%、实现 / 签核 QoR 闭环

Synopsys 在 DAC 2026 期间宣布与 Microsoft 合作推出行业首个可在 Microsoft Discovery 上评估的自主 EDA 工作流，并由 AMD 积极评估用于其下一代产品开发——把 agentic AI 从"任务自动化"推向"长程工程执行（long-running autonomy）"。
① 全自主 debug closure 工作流：由 Microsoft Discovery 编排的、全自主 AI 驱动验证与根因分析（RCA）工作流，汇聚领域专用与任务级智能体来定位设计失效、自动化 debug 任务、加速验证；早期评估显示 debug 周期缩短 25–40%，节省数周工程投入、提升硅质量。
② 全自主实现与签核（implementation & closure）工作流：借 Synopsys 实现智能体 + Fusion Compiler（运行于 Azure），汇聚领域专用与任务级智能体自动化实现 QoR 调优与收敛，初期结果显示 QoR 改善。
核心看点：这是本站已跟踪 Synopsys×NVIDIA 全自主工程智能体（07-29，验证 50× / AMS 3× / 热 CAE 自治）的姊妹里程碑——同一 AgentEngineer™ 平台，但首次落到 Microsoft Discovery 云科学发现平台、且有 AMD 作为头部芯片客户拉动路线；与 Cadence ChipStack（10×）、Siemens Fuse（self-verifying）共同坐实"三巨头 DAC 2026 集体从工具转向长程自主智能体"的趋势。来源：news.synopsys.com。

📐 VPR-Evolve：多智能体驱动的 FPGA 布局布线算法演化——LLM 智能体直接演化 VPR 源码，复合得分最高 +2.7%、关键路径延迟降 9.8%

CAD 工具通常对结构 / 时序差异巨大的电路套用同一套固定、手工设计的算法；常见做法是调超参，但超参调优只能在固定算法已实现的行为里选，既限制 QoR 上限、又需大量昂贵的布局布线评估。本文提出 VPR-Evolve：一个多智能体框架，通过对每个设计演化开源 FPGA 打包-布局-布线引擎 VPR（Verilog-to-Routing 流）的源码来特化它——用 LLM 智能体提出、实现并评估代码级修改，共享记忆记录历史结果并指导后续演化；每个候选都经完整 VPR 构建与运行，直接优化"关键路径延迟（CPD）+ 布线线长（WL）+ 工具运行时（RT）"的加权复合得分。
结果：在 5 个 VTR-9 基准上，VPR-Evolve 较 stock VPR 复合得分最高 +2.7%；相对 stock VPR，CPD 最高降 9.8%、布线 WL 最高降 18.1%、工具 RT 最高降 79.3%；相对超参调优基线，CPD 最高降 6.0%、WL 最高降 2.2%、RT 最高降 7.8%。
核心创新：把"为设计特化 CAD 工具"从超参调优升级为LLM 多智能体驱动的代码级算法演化——延续本站物理设计（布局 / 布线 / 单元插入）与"智慧体协作的物理设计 QoR 优化"（AgenticPD / FAPlace / CoEvoP&R）主线，且直接作用于开源 VPR 引擎、可复现。

多智能体 FPGA布局布线 VPR 代码演化 LLM智能体 物理设计

⚡ VClare：修复 LLM Verilog 生成中的"不规范规格"——Spec-Level + Sim-Level 双范式修复，单模块 pass 率 +12.7%、多模块 +13.7%

LLM 在从自然语言规格生成 Verilog 上展现潜力，但人工撰写的规格常含语义缺陷（模糊、矛盾、不完整），会显著拉低生成硬件的质量。本文给出首个对不规范规格的系统研究，并提出自动化框架 VClare 来修复它们、提升最终 Verilog 设计质量。
框架探索两种互补修复范式：Spec-Level Repair 直接在规格文本上做 LLM 驱动的不一致挖掘；Sim-Level Repair 采用基于仿真的行聚类 + 可选的测试时不一致仲裁。同时提出两个系统性注入规格缺陷的新基准——一个源自 VerilogEval-human（单模块任务），另一个源自 ComplexVDB（含 53 个更贴近真实工程场景的多模块任务）。
结果：单模块任务上 VClare 有效修复规格缺陷、使生成 Verilog 的 pass 率提升 12.7%；多模块任务上提升达 13.7%——彰显 LLM 在前端硬件设计中的规格修复能力。
核心创新：首次把"规格质量"作为 LLM RTL 生成的可修复前置于生成的一环——延续本站"理解先于编码"（VeriRefine 五层审计 / EstRTL / LongRTL）与 LLM RTL 生成-验证闭环主线，并补齐"规格本身有缺陷时怎么办"的研究空白。

LLM Verilog生成 规格修复 RTL生成 基准 前端硬件设计

arXiv · cs.AI / cs.AR / cs.CR · 2026-07-28 · Jingbo Zhang, Haoxiang Sun, Wenbo Wang, Wenbo Zhang

✅ ContractHIL-HLS：契约对齐的多智能体 HLS 工作流——硬件在环反馈贯通内核到板级，pass@1 70.4%、板级运行时 207→52ms

本文提出 ContractHIL-HLS：一个面向实用化高层次综合（HLS）工程的契约对齐多智能体工作流，有三方面贡献。
① 结构化契约作为语义对齐与任务执行工件，把自然语言需求翻译为显式接口、约束、校验检查与回滚规则；② 把硬件信息接入反馈环——将 HLS、Vivado、PYNQ 运行时、功耗与失败证据回馈生成，把 LLM 辅助 HLS 从内核代码推进到系统与板级收敛；③ 按语义下降与执行任务（而非对话角色）分解智能体：Contract Agent 把自然语言降为契约、HTML Agent 把契约渲染为持久结构化 HTML、Hardware-in-the-Loop Agent 用实测证据实现并修订设计。
结果：在 94 个本地可执行的 HLS-Eval 任务上，结构化契约带来最大小设计增益，估计单样本 testbench pass 率从 64.0% 升至 70.2%；完整流程 pass@1 达 70.4%、pass@5 达 76.6%。另在板级测试的 ML-KEM/ML-DSA 后量子密码（PQC）安全消息加速器上验证：保留的双比特流组织将六消息平均文本运行时从 207.3ms 降至 52.4ms，两版镜像均有正 routed WNS，且保持解密消息验证。代码已开源（BJUT-CS316-LAB/ContractHIL-HLS）。
核心创新：用"契约 + 硬件在环反馈"把 LLM 辅助 HLS 从内核代码升级为板级可收敛的多智能体工程流——延续本站"智慧体协作的 RTL 生成-验证-反馈闭环"（HLS-LeVeri / VeriPilot）与 HLS 自动化主线。

HLS 多智能体 契约对齐 硬件在环 验证反馈 板级收敛
