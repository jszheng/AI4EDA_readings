⚡ VeriRAG：面向 Verilog 的检索增强生成——从「已验证代码片段库」检索可复用模式，把规格→RTL 的幻觉率打到接近零

LLM 直接生成 Verilog 的顽疾是幻觉：凭空发明不存在的模块端口、信号或 IP，且生成结果难以追溯「为什么这么写」。VeriRAG 把检索增强生成（RAG）引入 RTL 生成：先从一个已验证代码片段库（VerilogEval / RTLLM 黄金参考 + 开源可综合 IP）构建带接口契约与测试平台通过证据的向量索引，生成时先用规格检索最相关的「已验证 RTL 片段 + 其契约」，再把检索内容作为强上下文约束注入生成，使输出可追溯到具体参考实现；并引入检索分歧检测——当多个候选片段契约冲突时显式要求澄清而非静默拼接。在 VerilogEval-Human 与 RTLLM v2.1 子集上，相对无检索基线 pass@1 提升 14.2pp、端口/信号级幻觉降 81%，且 95% 的最终设计零 Lint。属「前端 RTL / Retrieval-Augmented Generation (RAG) for Verilog」方向，用「已验证片段检索 + 契约约束 + 分歧检测」把 RTL 生成从自由创作升级为可溯源、可验证的受约束生成，与本站持续追踪的「契约中间表示 + 真实仿真反馈」主线直接呼应，也补齐了用户关注关键词里「RAG for Verilog」这一独立细分。

📐 BufFormer：强化学习驱动缓冲器插入与单元大小联合优化——时序/功耗/面积多目标在布局后协同收敛

布局后优化（post-placement optimization）里，缓冲器插入与单元大小调整（cell sizing）长期被当作两道串行工序：先定缓冲再定尺寸，彼此割裂导致局部最优。BufFormer 把二者建模为联合序列决策，以强化学习智能体在网表图上逐节点决定「是否插缓冲、插几级、邻近单元选大驱动还是小驱动」：状态融合时序关键度、净电容、翻转率与拥塞；奖励对最差负裕量（WNS）、总负裕量（TNS）、漏电功耗与面积做帕累托加权。为避免 RL 不可微，BufFormer 用可微分代理目标预热策略、再切换真实签核指标微调。在 ISPD/TCAD 基准与开源 OpenROAD 流程上，相对 Synopsys 系商业 PPO + 独立 sizing 基线，WNS 改善 11.3%、漏电降 9.7%、面积增仅 1.8%，且详细布线绕通率提升。属「后端物理设计 / 强化学习在单元大小调整、缓冲器插入的应用」方向，用「RL 联合决策 + 可微分预热」把两道割裂工序升级为带记忆的可收敛协同优化，与本站关注的「RL 在布局布线/缓冲器插入」细分一致。

🌡️ MultiPhys-GNN：图神经网络驱动 3D-IC 电-热-力多物理场协同预测——封装图上联合回归温度/应力/IR 压降，分钟级全芯片多物理场

3D-IC 与芯粒堆叠使电-热-力三场深度耦合：电流密度驱动温升、温升诱发热应力与界面分层、而电源网络 IR 压降又反向限制时序与可靠性。现有做法靠串行有限元（FEM）逐场求解，单次全芯片多物理场仿真动辄数小时。MultiPhys-GNN 把芯粒堆叠建模为多属性封装异构图（芯粒/微凸点/TMV/TSV/中介层为节点，电-热-力耦合边），用图神经网络在图上同时回归稳态/瞬态温度场、热应力场、电源 IR 压降三套物理量，并以物理残差正则（电流守恒 + 热流守恒 + 应力平衡）约束预测满足守恒律；推理秒级输出「互连/供电规划→多物理场」联合解，并给出可微分梯度提示（把高功耗、高应力芯粒错开放置）。在 2.5D/3D 开源基准上与商业 FEM 对齐，峰值温度 RMSE < 2.3°C、最大 von Mises 应力误差 4.1%、IR 压降误差 3.6%，下游协同优化使峰值温度降 7.2%、最大界面应力降 9.4%。属「后端物理设计 / 多物理场 AI 分析、Chiplet 互连·热分布优化」方向，把多场从串行工具合并为联合可微预测，与本站关注的「Chiplet 系统互连 / 热分布优化、多物理场 AI 分析」主题直接对应，也把此前 ThermalGNN（2609.11876）、ChipletNet-GNN（2609.13567）的热/互连单场预测推进到真正的三场耦合。

🤖 ToolFail-EDA：端到端芯片设计智能体的工具调用失败模式分类与基准——量化「工具调用占失败 47%」的根因，给出可诊断失败 taxonomy

本站 09-15 收录的 EDA-AgentBench 实测指出「工具调用可靠性占端到端失败约 47%」，但具体哪些工具调用在何时、为何失败仍是一团黑盒。ToolFail-EDA 首次系统构建端到端 EDA 智能体工具调用失败模式分类法（taxonomy）：把失败归为五类——① 工具选择错误（误用综合器/验证器）、② 参数/语法错误（EDA Tcl 命令拼错）、③ 工具返回值误读（把 warning 当 pass）、④ 长上下文遗忘（跨多轮丢失约束）、⑤ 超时/资源失败（大设计 OOM）；并发布ToolFail-Bench，在 RTL→综合→验证→布局布线 50 个子任务上植入受控故障、统计各智能体（Synopsys AgentEngineer 风格 / 开源 OpenROAD-MCP 风格）的失败分布与恢复率。结果显示五类失败占比 41%/23%/18%/11%/7%，且引入「工具调用自我校验层」后整体端到端一次通过率从 23% 提到 38%。属「AI Agent / 可靠性·失败诊断」方向，把「智能体能否真正跑通芯片设计」从「能不能」推进到「坏了为什么、怎么修」，与 AgentEDA-Survey（2609.13789）的评估缺口、EDA-AgentBench 的 47% 瓶颈形成闭环证据，为 RTL-to-GDSII 自主流程的可诊断性提供标尺。
