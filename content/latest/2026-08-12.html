🇨🇳 UCAgent 开源 + HimaFormal MC：国产形式化验证智能体落地——自然语言生成 SVA 断言、COI 覆盖率驱动自动补全，PicoRV32 实测提速 16×

上海阿卡思（华大九天战略参股）联合北京开源芯片研究院、中科院计算所推出「HimaFormal MC + UCAgent」智能形式化验证方案，并在 WAIC 2026 亮相。UCAgent 是开芯院自研的基于 LLM 的自动化芯片验证智能体，源码已在 GitHub 开源（XS-MLVP/UCAgent），支持简单模块（约 1000 行 Verilog 以下）100% 自动验证，并可通过 MCP 与 OpenHands / Copilot / Claude Code / Gemini-CLI / Qwen-Code 等通用 Code Agent 深度协同。方案以「自然语言生成断言 → HimaFormal MC 形式化验证 → 反例/覆盖率分析 → 自动补充断言」的 AI 驱动闭环，替代传统「人写断言 + 人跑工具 + 人补断言」模式；基于逻辑影响锥（COI）覆盖率驱动自动迭代直至 100%。在开源 RISC-V 核 PicoRV32 实测中，覆盖率从 53% 提升至 91%、全流程约 30 分钟，较人工约 8 小时提速约 16×。已落地多家企业真实项目（国内头部 AI 芯片厂商对接内部 LLM 实现全链路形式化验证无人值守；深圳 SSD 主控芯片企业将 UCAgent 作为内部数字验证统一 AI 接口并二次开发）。华大九天还基于该框架搭建 HimaFormal HiLEC+UCAgent、HimaFormal EC+UCAgent 两套标准化联合流程，降低 C/C++→RTL 高阶等价性检查门槛。这是国产「形式化验证 + LLM 智能体」从科研走向企业级落地的重要标志。

🔧 veriflow-cc：用 Claude Code 一键打通 RTL 设计流水线——从需求到综合（iVerilog/Yosys），子代理嵌套 + 行为驱动验证 + 状态可恢复

veriflow-cc 是一个 Claude Code 驱动的 RTL 设计流水线技能（skill），将 Claude Code 主会话作为「流程大脑」：控制阶段切换、调用子代理做 RTL 生成、处理错误与回滚，状态持久化到 JSON 可断点恢复。四阶段严格顺序执行：① spec_golden（生成 spec.json + golden_model.py 参考模型与测试向量）；② codegen（vf-coder 子代理逐模块并行生成 RTL）；③ verify_fix（iverilog/cocotb 内联仿真 + 错误恢复，3 次重试预算）；④ lint_synth（iverilog + Yosys 并行 lint 与综合）。工程亮点：golden_model.py 同时作为参考模型与测试向量生成器，由 vcd2table.py 做波形 diff 辅助错误恢复；内置 5 个内联 Verilog-2005 mini-pattern（FSM / Hash round 等）引导 vf-coder；提供 cocotb 优先仿真、跨模块时序、覆盖率分析、形式证明（formal_prove.py 经 SymbiYosys）、多候选 RTL 选择（测试时缩放）、跨项目 bug pattern 自学习（self_improve.py，benchmark 门禁可逆）等能力；错误恢复按类型分类回滚（syntax→coder、logic→microarch、timing→timing）。项目零 Python 依赖、无需 LangGraph/LangChain/Streamlit，安装即用（/vf-rtl <project_dir>），附带 ChaCha20 端到端示例。这是把「需求 → 黄金模型 → RTL → 仿真验证 → lint/综合」工程化闭环封装为可复用 Claude Code 技能的代表作，对「开源 EDA AI Skills / Agents 新能力」方向有直接参考价值。

🧠 HINT：面向 LLM 驱动 RTL 生成的「可执行硬件意图」中间表示层——7/7 算子案例产出合规可综合 RTL，面积较人工实现降 5.0%–26.2%

用大语言模型（LLM）生成实现级质量的 RTL 一直很难，因为直接生成必须在「解析微架构」的同时「产出并调试底层代码」。HINT 在行为级规约（或可执行 oracle）与 RTL 之间插入一层可执行的「硬件意图」中间表示：把 RTL 相关的微架构选择显式化，支持 RTL 生成前的预检查，并给出明确的「RTL 下沉义务」。作者用最小单智能体流程与完整分阶段流程两种配置评估：在 7 个算子案例上，HINT 介导路线无需综合后 QoR 精修即产出 7/7 合规可综合 RTL；而 Direct C2RTL 适用 5 例、成功 5/5，C2HLSC 适用 5 例、仅成功 1/5。在匹配的 Design Compiler 综合下，HINT 相对 5 份人工 RTL 实现面积降低 5.0%–26.2%，相对 5 份被接收的 C2RTL 结果降低 8.9%–86.1%；RealBench AES/SDC 以及综合到 561.67k μm² 的 Vortex VPU 进一步验证了其在协议密集、存储密集与层次化设计上的能力。这代表「LLM 直出 RTL」之外一条更可控、可验证的 RTL 生成路径。

🤖 ZhuLong：执行接地的 LLM EDA 脚本智能体——统一 MCP 工具 + 离线 API 自探索，PyAether 基准 Pass@1 78.5%

EDA 脚本依赖特定工具、常无文档的 API，是现有 LLM 难以覆盖的长尾瓶颈。ZhuLong 是面向 PyAether 与 SKILL 的执行接地 LLM 编码智能体，把 API 检索、文档检视与沙箱执行经统一 MCP 工具结合，并用离线 API 自探索机制通过对抗性实验推断无文档 API 行为。在 EDA-Eval-PyAether（158 个带断言执行的真实任务）基准上，完整系统于商用 Empyrean Aether 环境取得 78.5% Pass@1，大幅超越纯 LLM 基线（23.6%）。消融显示沙箱执行是主要驱动力（移除后降 41.2 个百分点），自探索机制额外贡献 3.2 个百分点精度提升与 22.1% 的单任务工具调用减少。在 20 个涉及未保存版图与原理图的交互任务上，PyAether 与 SKILL 分别取得 60.0% 与 50.0% Pass@1。

⚡ ARMOR：以节点压缩缓解 RTL 仿真前端瓶颈——CPU 设计 1.6×、AI 加速器 2.7× 加速

RTL 仿真是芯片设计不可或缺的一环，高性能仿真器通常把 RTL 图中每个节点下沉为一段指令序列，但这会急剧膨胀代码体、超出指令缓存容量、造成前端瓶颈。作者剖析发现，最先进 RTL 仿真器中 超过 50% 的流水线停顿源于 CPU 前端。ARMOR 提出以节点压缩缓解该瓶颈：利用展开后 RTL 图暴露的数据并行性，以及逐节点下沉造成的比特空间利用不足，用位级数据并行把多个节点同时压缩，使单条指令序列服务多个节点而非每节点一条。关键技术：①模块感知的同构子图识别，跨模块实例利用结构同构系统性定位子图级压缩机会；②对齐感知的密集打包，按数据流依赖分组并保留数据复用，配合贪心合并提升比特利用率；③统一位级并行执行。实验上，ARMOR 在 CPU 设计上取得 1.6×、在 AI 加速器上取得 2.7× 加速，对大模型/AI 芯片的长时仿真尤其有价值。

🔍 IDRAAK：从多智能体 NLP 到少样本提示的技术需求语义漂移检测——单 LLM+6 少样本即达 F1=0.983，复杂 agentic 未必更优

跨语言翻译技术需求会引入语义漂移——数值约束、极性、模态等规约关键语义被改变。IDRAAK 用一种语言无关的语义需求表示（SRR）来检测这类漂移，并评估了 6 种工作流，从确定性比较到多智能体验证再到少样本提示。在 10 个工程领域 300 条需求的 890 个合成扰动上，单次 LLM 调用 + 6 个少样本示例即达 MCC=0.888、F1=0.983，优于所评估的结构化与多阶段方案；在 PAWS-X（5 语言）与 XNLI（7 语言）上进一步揭示结构化与 LLM 方法的互补强弱。核心结论颇具反直觉：更高的 agentic 复杂度并不必然提升语义漂移检测，简单少样本提示已是高效且强力的替代。这对「需求→规约→RTL」链路中需求一致性的自动化校验有直接借鉴意义。

🤖 ArchAgent v2：把智能体式微架构搜索扩展到多级数据预取——DPC4 上自动设计三级预取器超越手工冠军方案（IPC +3.8%）

ArchAgent v2 把自动化微架构搜索从单级缓存替换策略扩展到多级数据预取。原 ArchAgent 曾在竞赛设定下发现单级缓存替换策略，但无法扩展到设计空间与自由度更大的多级预取。为此引入两项机制：①级联演化搜索，按缓存层级依次演化并冻结各级预取器，细分设计空间；②硬件可实现性反馈环，把实时面积/规模估计直接嵌入演化过程。在第 4 届 Data Prefetching Championship（DPC4）同规则下，ArchAgent v2 自动设计的三级预取器超越了手工冠军方案：整体几何平均 IPC 较基线提速 3.8%、较上届冠军 BertiGO 提升 0.3%；低带宽单核配置下提速 4.6%（BertiGO 仅 2.6%）。作者对一次逾 12,000 个候选设计的演化做了剖析，揭示了自动化演化智能体如何探索与综合复杂微架构逻辑——是「智能体式架构发现」走向实用的重要一步。

🔋 ReVolt：面向 2.5D PIM Chiplet 的 PDN 感知电压跌落控制——LSTM PDN 代理预测，EDP 平均降 76× 且不损推理精度

基于存内计算（PIM）的 2.5D 多 chiplet 平台是 ML 工作负载的关键使能技术，但其性能受供电网络（PDN）制约：各 chiplet 电流需求随时空变化，引发电压跌落（voltage droop），导致电压违例、性能下降并影响推理精度。ReVolt 提出以动态运算单元（OU）为基元的框架来缓解跌落：用 LSTM-based PDN 代理在运行时预测每 chiplet 的供电电压轨迹，从而主动调节 OU 规模以平抑跌落事件；把 OU size 当作控制旋钮，在维持计算精度的同时调控 chiplet 级电流需求。实验表明，ReVolt 在不牺牲 ML 模型推理精度的前提下杜绝电压跌落违例，相对既有固定与动态 OU 基线平均降低 76× 的 EDP（能耗-时延积）。这是「ML 代理模型 + 控制理论」用于 chiplet 供电稳定性的代表性工作。

🔗 C2C-Explorer：面向 LLM 云计算系统的片间互连架构探索框架——贝叶斯 DSE，DeepSeek-R1-671B 上 goodput +44.1%、显存 -98.4%

大模型 Scaling 要求多处理器芯片架构，使片间（C2C）通信愈发关键。但为 LLM 负载设计高效 C2C 硬件面临三难：生成真实 LLM 专属 C2C 流量、在规模上准确仿真硬件级通信、高效探索指数级设计空间。C2C-Explorer 是一个自适应贝叶斯 DSE 框架，把 LLM 负载驱动的流量生成器、可扩展互连仿真器（支持开关/全 mesh，规模达 512 chip）与度量引导的评估器整合成「负载→硬件」的协同优化流水线。以 FPGA 原型验证，其 C2C 仿真器在多种流量模式下端到端时序误差仅 2.46%–8.23%，混合周期-事件模型较纯周期精确基线加速达 7.8×；应用于 32-XPU 的 DeepSeek-R1-671B 推理负载，C2C-Explorer 找到的配置使 goodput 提升 44.1%、显存降低 98.4%。项目已开源（github.com/Selinaee/C2C-Explorer），对 chiplet 系统互连协同设计是直接可用的工具。

🚀 FSGen：带早期 PPA 估计的敏捷 LLM 注意力加速器生成框架——能效高 1.4× 或 速度快 10×，FoM 高 58×

随着 LLM 成为众多领域的重要负载，如何高效生成最优 AI 芯片加速器设计仍是开放难题，现有方法缺乏端到端的设计空间探索（DSE）方法论。FSGen 是一个面向注意力类 LLM 加速器的敏捷生成框架，并配备早期 PPA 估计器：支持融合算子数据流与稀疏，拥有多样设计空间，在相近 PPA 指标下找到能效高 1.4× 或 速度快 10× 的设计；Pareto 最优设计在广阔 LLM benchmark 上表现更优，品质因数（FoM）高 58×。得益于精度优于既往方法的 PPA 估计器，设计探索也大幅提速。这是把「生成式 DSE」落到 LLM 加速器这一具体且高价值场景的务实尝试。

🌡️ SAU-FNO：自注意力 U-Net 傅里叶神经算子用于 3D-IC 热仿真——SOTA 精度，较传统 FEM 加速 842×

3D-IC 因功率密度升高，热管理日益困难；传统 PDE 求解准确但太慢，难以支撑迭代式设计，而 FNO 等 ML 方法存在高频信息丢失与对高保真数据依赖的问题。SAU-FNO（Self-Attention U-Net Fourier Neural Operator）把自注意力与 U-Net 同 FNO 结合，兼顾长程依赖与局部高频特征；并采用迁移学习用低保真数据微调，降低对昂贵高保真数据集的需求。实验显示 SAU-FNO 取得当前最优的 3D-IC 热预测精度，较传统 FEM 方法加速 842×，是先进 3D-IC 热仿真的有效工具，对多物理场 AI 分析有直接价值。
